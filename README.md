## About Me

I'm a software engineer focused on **Web3, AI-assisted systems, and full-stack product development**. Most of what I build sits at the intersection of two of those — decentralized applications with an AI layer on top, or ML systems wired into a usable product rather than left as a notebook.

I like taking a project from a blank repo to a deployed, working demo. Several of the projects below are live, not just code — because a system that hasn't shipped hasn't really been tested.

- 🔐 **Web3 for real problems** — data ownership, healthcare records, and trade settlement, not speculative tokens
- 🤖 **AI as infrastructure** — using LLMs (Gemini) for validation, agent orchestration, and decision support inside larger systems, not as a standalone chatbot demo
- 🛡️ **Security-minded** — built detection and honeypot systems for scam and fraud patterns
- 🌍 **Open source contributor** — merged pull requests into projects maintained by Microsoft and QGIS, alongside my own repositories

### 🩺 [MediChain](https://github.com/NisargaK-21/Medichain)
**A decentralized healthcare records platform.**

Patients control access to their own medical data instead of a hospital's central database holding it. Record hashes are stored on the Ethereum blockchain for immutability, actual documents stay encrypted off-chain, and doctor access is granted or revoked through smart contracts. A Gemini-powered assistant helps users navigate privacy decisions.

**Problem solved:** Patients have no real control over who can view or hold their medical history.

`React` `Node.js` `Solidity` `MetaMask` `Gemini API`

[Live Demo](https://medichain-website-krkh5ztrx-nisargak-21s-projects.vercel.app/) · [Repository →](https://github.com/NisargaK-21/Medichain)

### 🛡️ [DataConsent](https://github.com/NisargaK-21/finaldataconsent)
**An on-chain "kill switch" for personal data.**

Replaces the standard, easily-ignored "unsubscribe" button with a smart contract (SovereignGate) that lets a user cryptographically revoke a third party's access to their data — with the revocation permanently recorded on Ethereum Sepolia. Private keys never leave the browser.

**Problem solved:** Data revocation today depends on trusting a company's backend, not on any provable guarantee.

`Solidity` `JavaScript` `Ethereum Sepolia` `Wallet Auth`

[Live Demo](https://finaldataconsent.vercel.app/) · [Repository →](https://github.com/NisargaK-21/finaldataconsent)

### 📊 [SettleTrack](https://github.com/NisargaK-21/Settletrack)
**A blockchain trade-settlement platform with ML-based risk scoring.**

Records trade settlements immutably on Ethereum smart contracts while a machine learning layer flags anomalies and assesses counterparty risk in real time, exposed through a REST API and a web dashboard.

**Problem solved:** Post-trade settlement is slow and opaque, with risk assessment usually happening after the fact.

`Solidity` `Python` `Node.js` `REST API` `ML Risk Scoring`

[Repository →](https://github.com/NisargaK-21/Settletrack)

### 🕵️ [Agentic Honeypot](https://github.com/NisargaK-21/honey-pot)
**An AI agent that detects and engages scam messages.**

A FastAPI service that scores incoming messages for scam intent, then hands off to an autonomous AI agent that holds a realistic multi-turn conversation with the suspected scammer to extract actionable intel — UPI IDs, phone numbers, phishing links — without revealing that it has detected them.

**Problem solved:** Static scam filters block messages; they don't extract intelligence from the sender.

`Python` `FastAPI` `AI Agents` `Scam Detection`

[Repository →](https://github.com/NisargaK-21/honey-pot)

</td>

### 🎮 [Devino](https://github.com/NisargaK-21/Devino)
**A gamified platform that teaches full-stack development by shipping.**

Guides learners through a structured pipeline — Frontend → Backend → Database → Auth → Deployment — where each stage must pass AI validation (Gemini) before the next unlocks, so users finish with a real deployed app instead of isolated tutorial exercises.

**Problem solved:** Most coding tutorials end at a local demo, not a deployed product.

`Next.js` `TypeScript` `Express` `MongoDB Atlas` `Gemini API`

[Repository →](https://github.com/NisargaK-21/Devino)

</td>
<td width="50%" valign="top">

### 🔎 [Micro-Dark](https://github.com/NisargaK-21/micro-dark)
**An ethical, offline proof-of-concept for detecting illegal-marketing language.**

Most anti-dark-web tooling focuses on finding listings or leaked credentials. This project instead studies the promotional *language patterns* used to market illegal goods, using a supervised text-classification model trained entirely on curated, offline data — no scraping, no Tor access, no live dark-web interaction.

**Problem solved:** Illegal markets persist partly through organized marketing tactics that are under-studied compared to the listings themselves.

`Python` `Text Classification` `FastAPI` `SQLite`

[Repository →](https://github.com/NisargaK-21/micro-dark)

## Development Philosophy

- **Ship before polishing.** Every featured project above has a live demo or a working local build — not just a README describing an idea.
- **Security and privacy are design constraints, not features to bolt on.** DataConsent, MediChain, and Micro-Dark all treat access control as a first-class concern from the start.
- **AI belongs inside the system, not in front of it.** I use LLMs for validation, agent orchestration, and decision support — embedded in a pipeline — rather than as a standalone chat wrapper.
- **Read the codebase before opening a PR.** My merged pull requests to Microsoft and QGIS repositories fixed real, scoped issues in unfamiliar codebases rather than superficial changes.
